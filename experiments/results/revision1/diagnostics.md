## D1b — D1 by target design stratum

Strata from the target's design class in `shared/testbed/pages/*.truth.json`:

- **has_attribute_signal** — `signal_attrs` contains at least one HTML attribute name (768 pairs);
- **NONE** — `signal_attrs` empty (47 targets, 188 pairs);
- **text_only_signal** — `signal_attrs` non-empty but only `text` (page_01 t_04; 4 pairs);
- **no_attribute_signal** = NONE + text_only_signal (48 targets, 192 pairs) — the row used in the paper.

Why condition 5 is false on every bundle and encoding for the text-only target: condition 5 (`Oracle.ComputeStableSignalPresence`) looks each `signal_attrs` entry up as an attribute NAME on the oracle element (`rawOracleEl.Attrs`) after checking bundle membership. `text` is not an HTML attribute — the DOM walk stores visible text separately (`ElementData.Text`), and `text` is a virtual key in `AttributeBundles` — so the lookup never succeeds and the target cannot pass P5 in any cell, by construction.

`signal_attrs` vocabulary across the 240 targets (entry: number of targets listing it): `aria-label`: 133, `data-testid`: 63, `id`: 50, `name`: 45, `href`: 20, `placeholder`: 10, `text`: 1, `type`: 1. The DOM walk records every HTML attribute of an element (`el.attributes`), so every entry except `text` is an attribute name. Targets whose `signal_attrs` contain a non-attribute signal: page_01 t_04 ['text'].

Checks: in the 960 B_full / B_noVolatile pairs the no_attribute_signal events are exactly the events with condition 5 = false, in both bundles (192 each, identical event sets); and the targets whose condition 5 is false on every B_full DOM encoding are exactly the no_attribute_signal targets. Bootstrap: same procedure, resampling the pages present in the stratum. With no discordant pairs the McNemar statistic and the OR are undefined (n/a / nan).
